## 项目愿景

打造一个能够**批量生产"销冠"的系统**，这是一个体系化工程，通过多个相互独立且具备独立市场价值的子项目组成生态系统。

### 核心业务流程

1. 入职培训
2. 画像匹配
3. 岗上评估
4. 资源分配
5. 画像优化
6. 销冠进阶
7. 画像建模
8. 招聘评估

---

## ⚠️ 架构优化说明

**发现的问题**: 原架构中每个子项目都需要实现自己的租户管理和用户认证，导致重复开发和数据孤岛。

**解决方案**: 新增 **子项目0: 多租户统一用户中心**，作为整个生态系统的最底层基础设施，所有其他子项目都依赖它。

**优势**:
- ✅ 统一身份认证（单点登录 SSO）
- ✅ 避免重复开发租户和用户管理
- ✅ 数据一致性保障
- ✅ 统一的权限管理体系
- ✅ 便于审计和合规

## 子项目详细说明

### 子项目 0: 多租户统一用户中心 ⭐ 新增

- **定位**: 统一身份层（最底层基础设施）
- **依赖**: 无（所有其他项目依赖它）
- **核心功能**:
  - **租户管理**: 租户 CRUD、配置、配额管理
  - **用户管理**: 用户注册、登录、信息管理
  - **统一认证**: JWT、OAuth2、SSO 单点登录
  - **统一授权**: RBAC 角色权限、资源权限控制
  - **会话管理**: Session、Token 刷新机制
  - **审计日志**: 所有用户操作记录
  - **租户隔离**: 数据物理/逻辑隔离策略
  - **API 网关**: 租户路由、限流、鉴权
- **技术特性**:
  - 高并发（支持 10000+ 并发用户）
  - 高可用（99.99% SLA）
  - 可扩展（支持 10000+ 租户）
  - 安全合规（SOC2、GDPR）
- **独立市场价值**: 企业级统一身份认证 SaaS（IAM 平台）
- **优先级**: ⭐⭐⭐⭐⭐ (第一个开发，所有项目的前置依赖)
- **预计周期**: 6-8周

### 子项目 1: 多租户AI知识库管理平台

- **定位**: 基础设施层
- **依赖**: 子项目0（统一用户中心）
- **核心功能**:
  - 多租户知识库管理
  - AI知识检索
  - 知识版本控制
  - 文档解析与向量化
  - RAG 问答能力
- **技术特性**:
  - 基于 WeKnora 开源框架
  - PostgreSQL + pgvector
  - 支持多种文档格式
- **独立市场价值**: 企业知识管理SaaS
- **优先级**: ⭐⭐⭐⭐⭐ (第二个开发)
- **预计周期**: 6-8周（已有 WeKnora 基础）

### 与其他子项目的集成方式

#### 认证流程

```
用户 → 子项目N的前端
  ↓
子项目N → 子项目0: POST /api/v1/auth/login
  ↓
子项目0 ← 验证账号密码
  ↓
返回 JWT Token
  ↓
子项目N存储Token → 后续请求携带Token
  ↓
子项目N → 子项目0: GET /api/v1/auth/verify (验证Token)
  ↓
返回用户信息和权限
  ↓
子项目N继续业务逻辑
```

#### 权限校验流程

```
用户请求 → 子项目N的API
  ↓
提取JWT Token
  ↓
子项目N → 子项目0: POST /api/v1/auth/check-permission
  Body: {
    "user_id": "xxx",
    "resource": "knowledge_base",
    "action": "create"
  }
  ↓
子项目0返回: { "allowed": true/false, "reason": "..." }
  ↓
允许 → 执行业务逻辑
拒绝 → 返回403错误
```

## 架构设计原则 (更新版)

1. **统一身份优先**: 所有子项目必须通过统一用户中心进行认证授权
2. **微服务架构**: 每个子项目独立部署，通过API通信
3. **多租户设计**: 核心系统支持多租户，数据物理隔离
4. **API优先**: 统一的API网关和契约
5. **数据隔离**: 租户间数据完全隔离
6. **可扩展性**: 支持横向扩展
7. **高可用**: 核心服务99.9%可用性
8. **安全性**: 数据加密、权限控制、审计日志
9. **单点登录**: 用户一次登录，访问所有子系统
