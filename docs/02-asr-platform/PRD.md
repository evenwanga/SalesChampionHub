## 📋 执行摘要

### 产品定义

ASR语音分析平台是一个**CPU友好型**的销售通话分析系统，提供实时和离线的语音转文本、话术分析、质量评估和多语言支持。系统专门针对销售场景优化，帮助销售团队提升沟通效果和业绩表现。

### 核心价值主张

- **准确识别**: 基于先进的ASR模型，准确率 >90%（中文普通话）
- **销售专注**: 内置销售场景关键词库和话术模板
- **实时反馈**: 支持实时转录和即时质量评分
- **成本可控**: CPU推理方案，无需昂贵GPU硬件
- **多租户隔离**: 完全集成子项目0，确保数据安全

### 关键指标 (KPIs)

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| **转录准确率** | >90% (中文) | 字错误率 (CER) |
| **转录延迟** | <2秒 (实时流) | 端到端响应时间 |
| **批量处理速度** | >15分钟音频/小时 | CPU处理吞吐量 |
| **话术识别召回率** | >85% | 关键话术命中率 |
| **系统可用性** | >99% | 月度uptime |
| **CPU占用** | <80% (峰值) | 系统资源监控 |

## 🎯 产品目标和背景

### 1.1 业务背景

销售团队面临的核心挑战:
- **质量评估困难**: 人工抽查通话录音耗时耗力，覆盖率低
- **话术合规性**: 难以确保销售人员使用标准话术
- **培训效果**: 缺乏客观数据评估销售技巧
- **客户洞察**: 无法系统性分析客户需求和反馈

### 1.2 产品目标

**主要目标**:
1. 提供准确、快速的语音转文本能力
2. 自动识别和评估销售话术质量
3. 生成通话质量报告和改进建议
4. 支持实时监控和离线批量分析

**次要目标**:
1. 积累销售语料库用于模型微调
2. 为AI陪练系统（子项目7）提供分析能力
3. 支持多语言（中英文为主）

### 1.3 目标用户

| 用户角色 | 使用场景 | 核心需求 |
|---------|---------|----------|
| **销售人员** | 回顾自己的通话录音 | 查看转录、话术评分、改进建议 |
| **销售经理** | 团队质量管理 | 团队通话统计、问题识别、趋势分析 |
| **培训师** | 培训效果评估 | 话术合规率、技巧应用情况 |
| **质检人员** | 通话质检 | 批量转录、关键词搜索、质量评分 |
| **系统管理员** | 运维管理 | 租户配置、模型管理、性能监控 |

### 2.2 用户故事 (User Stories)

#### 优先级: P0 (必须实现)

**US-2.1**: 作为销售人员，我希望上传通话录音并获得文字转录，以便快速回顾通话内容。

**验收标准**:
- 支持常见音频格式（WAV, MP3, M4A）
- 文件大小限制: ≤100MB
- 转录准确率: >90% (中文普通话)
- 处理时间: ≤ 音频时长 × 0.5

**US-2.2**: 作为销售人员，我希望看到自己的话术评分，以便了解哪些方面需要改进。

**验收标准**:
- 评分维度: 开场白、需求挖掘、异议处理、成交话术
- 每个维度给出0-100分
- 标注具体话术片段
- 提供改进建议

**US-2.3**: 作为销售经理，我希望批量分析团队成员的通话录音，以便识别培训需求。

**验收标准**:
- 支持批量上传（最多50个文件）
- 异步处理，支持进度查询
- 生成团队统计报告
- 识别共性问题

#### 优先级: P1 (重要)

**US-2.4**: 作为销售人员，我希望实时查看通话转录，以便在通话中调整策略。

**验收标准**:
- WebSocket实时推送
- 延迟: <2秒
- 支持断点续传
- 显示置信度

**US-2.5**: 作为质检人员，我希望搜索包含特定关键词的通话录音，以便快速定位问题通话。

**验收标准**:
- 支持全文搜索
- 支持多条件过滤（日期、人员、评分）
- 高亮显示关键词
- 导出搜索结果

**US-2.6**: 作为系统管理员，我希望配置自定义话术模板和关键词库，以便适应不同销售场景。

**验收标准**:
- 支持租户级别配置
- 话术模板CRUD
- 关键词库导入/导出
- 立即生效

#### 优先级: P2 (可选)

**US-2.7**: 作为销售人员，我希望看到客户和销售的对话分离，以便更清楚地分析对话流程。

**验收标准**:
- 自动识别说话人
- 区分客户/销售
- 标注说话时长占比
- 可视化对话时间轴

**US-2.8**: 作为培训师，我希望对比优秀销售和普通销售的话术差异，以便制作培训素材。

**验收标准**:
- 支持多人对比视图
- 高亮话术差异
- 导出对比报告
- 可添加批注

## 🏗️ 技术约束

### 4.1 硬件约束

**CPU优先原则**: 由于硬件限制，系统必须基于CPU推理，不依赖GPU。

**推荐配置**:
- CPU: 8核以上（建议16核）
- 内存: 16GB以上（建议32GB）
- 存储: 500GB SSD
- 网络: 千兆网络

### 4.2 技术栈约束

**必须使用**:
- 编程语言: Go（与子项目1保持一致）
- 数据库: PostgreSQL 16（与子项目0共享）
- 缓存: Redis 7（与子项目0共享）
- 容器化: Docker + Docker Compose

**推荐使用**:
- ASR引擎: Whisper (OpenAI) / Paraformer (阿里)
- 推理框架: ONNX Runtime / Torch (CPU模式)
- 音频处理: FFmpeg
- 对象存储: MinIO / S3

### 4.3 模型约束

**CPU友好型模型选择原则**:
1. 模型大小: <1.5GB
2. 单样本推理时间: <1秒/秒音频 (CPU)
3. 内存占用: <4GB
4. 支持量化: INT8/FP16
5. 中文优化: 中文训练数据 >1000小时

### 4.4 成本约束

**目标**:
- 单个转录任务成本: <¥0.05
- 服务器月成本: <¥2000 (100小时音频/天)
- 存储成本: <¥0.001/分钟音频
