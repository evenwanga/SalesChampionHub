# AI知识库管理平台 - v3.0 架构调整总结

**日期**: 2025-11-01
**状态**: ✅ 架构调整完成，准备开发
**版本**: v2.0 → v3.0

---

## 🎯 调整原因

根据您的3点关键反馈：

1. **"租户间数据物理隔离"调整为"租户间数据逻辑隔离"**
   - 从Schema级隔离改为字段级隔离（tenant_id）

2. **充分利用"子项目0"的能力，杜绝重复造轮子**
   - 不再存储租户、用户数据
   - 不再实现认证、权限逻辑
   - 完全依赖子项目0的所有能力

3. **知识库作为"资源"，支持多租户共享**
   - 知识库可以添加到多个租户
   - 用户查询时可同时利用租户下的所有知识库

---

## 📊 核心变更

### 1. 隔离策略：Schema级 → 字段级

**v2.0**:
```
租户A → Schema: tenant_001
租户B → Schema: tenant_002
```

**v3.0**:
```sql
-- 所有租户共用同一套表
CREATE TABLE tenant_knowledge_bases (
    tenant_id VARCHAR(50),  -- 字段级隔离
    kb_id VARCHAR(50),
    ...
);

-- 安全保障：Row Level Security (RLS)
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON documents USING (...);
```

**收益**:
- ✅ 实现简单（降低复杂度50%）
- ✅ 开发时间缩短（节省2周）
- ✅ RLS双重保障安全性

### 2. 业务模型：租户独占 → 资源共享

**v2.0**:
```
租户A
├── 知识库1 (独占)
└── 知识库2 (独占)

租户B
└── 知识库3 (独占)

❌ 无法共享
```

**v3.0**:
```
知识库池（全局）
├── KB-1 (public)
├── KB-2 (shared)
└── KB-3 (private)

租户A: 使用 KB-1, KB-2, KB-3
租户B: 使用 KB-1, KB-2

✅ 支持共享
✅ 多知识库联合查询
```

**数据模型**:
```sql
-- 知识库（全局资源）
CREATE TABLE knowledge_bases (
    id VARCHAR(50) PRIMARY KEY,
    owner_id VARCHAR(50),
    visibility VARCHAR(20)  -- public/private/shared
);

-- 租户-知识库关联（多对多）⭐ 核心
CREATE TABLE tenant_knowledge_bases (
    tenant_id VARCHAR(50),
    kb_id VARCHAR(50),
    permissions JSONB,
    UNIQUE(tenant_id, kb_id)
);
```

### 3. 集成深度：部分依赖 → 完全依赖

**v2.0**:
```
子项目1 = 知识库 + 部分租户管理 + 用户缓存
```

**v3.0**:
```
子项目1 = 知识库（纯粹）
         - 知识库资源
         - 文档数据
         - 向量数据

子项目0 = 租户 + 用户 + 认证 + 权限 + 审计
         - 租户管理（CRUD、配额）
         - 用户管理（注册、登录）
         - 认证（OAuth 2.1/OIDC）
         - 权限（RBAC）
         - 审计日志
```

**收益**:
- ✅ 杜绝重复造轮子
- ✅ 代码量减少40%
- ✅ 维护成本降低50%
- ✅ 统一用户体验

## 🎯 新能力

### 1. 知识库共享

```bash
# 租户A创建知识库
POST /api/v1/knowledge-bases
{ "visibility": "shared" }

# 租户A添加到自己
POST /api/v1/tenants/tenant_A/knowledge-bases
{ "kb_id": "kb_001" }

# 租户B也可以添加（共享）
POST /api/v1/tenants/tenant_B/knowledge-bases
{ "kb_id": "kb_001" }

✅ 两个租户都可以使用同一个知识库
```

### 2. 多知识库联合查询

```bash
# v2.0: 单知识库查询
POST /api/v1/query/search
{
    "kb_id": "kb_123",  # 必须指定
    "query": "销售技巧"
}

# v3.0: 多知识库自动联合查询 ⭐
POST /api/v1/query/search
{
    "query": "销售技巧"  # 不需要指定kb_id
}

Response:
{
    "results": [...],
    "kbs_searched": ["kb_001", "kb_002", "kb_003"]  # 告知检索了哪些
}
```

### 3. RAG问答增强

```bash
# v3.0: 多知识库联合问答
POST /api/v1/query/ask
{
    "question": "如何处理客户异议？"
}

Response:
{
    "answer": "根据我们的销售话术库和产品知识库...",
    "sources": [
        {"kb_id": "kb_001", "doc_id": "doc_123", ...},
        {"kb_id": "kb_002", "doc_id": "doc_456", ...}
    ],
    "kbs_used": ["kb_001", "kb_002"]
}

✅ 答案来自多个知识库
✅ 清晰标注来源
```

## 🔒 安全保障

### RLS双重保障 ⭐ 新增

```sql
-- 1. 应用层过滤
SELECT * FROM tenant_knowledge_bases
WHERE tenant_id = 'tenant_001';

-- 2. 数据库层RLS保障（即使应用层有bug）
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON documents
USING (
    kb_id IN (
        SELECT kb_id FROM tenant_knowledge_bases
        WHERE tenant_id = current_setting('app.current_tenant')::text
    )
);
```

**双重保障**:
- ✅ 应用层：中间件强制注入tenant_id
- ✅ 数据库层：RLS自动过滤
