## 🎯 核心概念

### 三级挂载模型

知识库可以挂载到三个层级，用户的访问权限是**累加**的：

```
租户 (Tenant)
├── 挂载 KB-1, KB-2, KB-3  ← 所有用户可访问
│
├── 组织A (Organization)
│   ├── 挂载 KB-4, KB-5  ← 组织A用户可访问
│   │
│   ├── 用户1
│   │   └── 挂载 KB-6  ← 仅用户1可访问
│   │
│   └── 用户2
│       └── 挂载 KB-7  ← 仅用户2可访问
│
└── 组织B
    ├── 挂载 KB-8
    └── 用户3
        └── 挂载 KB-9

用户1可访问: {KB-1, KB-2, KB-3} ∪ {KB-4, KB-5} ∪ {KB-6}
            = 6个知识库
```

## 📊 数据模型

### 核心表：knowledge_base_mounts

```sql
CREATE TABLE knowledge_base_mounts (
    id BIGSERIAL PRIMARY KEY,
    kb_id VARCHAR(50) REFERENCES knowledge_bases(id),

    -- 挂载类型（三选一）
    mount_type VARCHAR(20) CHECK (mount_type IN ('tenant', 'organization', 'user')),

    -- 挂载目标（根据类型使用不同字段）
    tenant_id VARCHAR(50),        -- 租户级
    organization_id VARCHAR(50),  -- 组织级（来自子项目0）
    user_id VARCHAR(50),          -- 用户级（来自子项目0）

    -- 权限
    permissions JSONB DEFAULT '{
        "can_read": true,
        "can_write": false,
        "can_delete": false
    }',

    is_active BOOLEAN DEFAULT true,

    -- 约束：同一KB不能重复挂载到同一目标
    UNIQUE(kb_id, mount_type, tenant_id),
    UNIQUE(kb_id, mount_type, organization_id),
    UNIQUE(kb_id, mount_type, user_id)
);
```

## 🔍 查询限制

### 初始限制：最多4个知识库

```go
// 用户查询时的知识库选择逻辑
func Search(ctx context.Context, req SearchRequest) {
    // 1. 获取用户可访问的所有知识库
    accessibleKBs := GetUserAccessibleKBs(userID)
    // 例如: [KB-1, KB-2, KB-3, KB-4, KB-5, KB-6]  // 6个

    // 2. 应用限制：最多4个
    var selectedKBs []string
    if len(accessibleKBs) <= 4 {
        selectedKBs = accessibleKBs
    } else {
        if len(req.KBIDs) > 0 {
            // 用户指定（验证权限）
            selectedKBs = validateAndSelect(req.KBIDs, accessibleKBs, 4)
        } else {
            // 智能选择最相关的4个
            selectedKBs = selectRelevantKBs(accessibleKBs, req.Query, 4)
        }
    }

    // 3. 在选定的知识库中检索
    return searchInKBs(selectedKBs, req.Query)
}
```

**为什么限制4个？**
- ✅ 控制查询性能
- ✅ 避免结果过于分散
- ✅ 保证响应时间
- ⚠️ 后续可根据性能调整（如提升到8个）

## 🔑 权限计算

### 获取用户可访问的知识库

```go
func GetUserAccessibleKBs(userID string) []string {
    user := getUserFromSubProject0(userID)  // 获取用户信息（含组织归属）

    var kbIDs []string

    // 1. 租户级知识库
    tenantKBs := db.Query(`
        SELECT kb_id FROM knowledge_base_mounts
        WHERE mount_type = 'tenant' AND tenant_id = ?
    `, user.TenantID)
    kbIDs = append(kbIDs, tenantKBs...)

    // 2. 组织级知识库
    if user.OrganizationID != "" {
        orgKBs := db.Query(`
            SELECT kb_id FROM knowledge_base_mounts
            WHERE mount_type = 'organization' AND organization_id = ?
        `, user.OrganizationID)
        kbIDs = append(kbIDs, orgKBs...)
    }

    // 3. 用户级知识库
    userKBs := db.Query(`
        SELECT kb_id FROM knowledge_base_mounts
        WHERE mount_type = 'user' AND user_id = ?
    `, userID)
    kbIDs = append(kbIDs, userKBs...)

    // 4. 去重
    return unique(kbIDs)
}
```

## 📡 API接口

### 挂载管理

```bash
# 租户级挂载（所有用户可访问）
POST /api/v1/mounts/tenant
{ "kb_id": "kb_123", "tenant_id": "tenant_001" }

# 组织级挂载（组织用户可访问）⭐
POST /api/v1/mounts/organization
{ "kb_id": "kb_123", "organization_id": "org_456" }

# 用户级挂载（仅该用户可访问）⭐
POST /api/v1/mounts/user
{ "kb_id": "kb_123", "user_id": "user_789" }

# 获取用户可访问的知识库 ⭐ 核心
GET /api/v1/user/accessible-kbs
Response: {
    "knowledge_bases": [
        {"id": "kb_001", "mount_type": "tenant", ...},
        {"id": "kb_002", "mount_type": "organization", ...},
        {"id": "kb_003", "mount_type": "user", ...}
    ],
    "total": 6,
    "query_limit": 4  // 一次最多查询4个
}
```

### 查询接口（支持知识库选择）

```bash
# 方式1: 自动选择（智能选择4个最相关的）
POST /api/v1/query/search
{ "query": "销售技巧" }

Response: {
    "results": [...],
    "kbs_searched": ["kb_001", "kb_002", "kb_003", "kb_004"],
    "kbs_total_accessible": 6
}

# 方式2: 用户指定（最多4个，从可访问范围中选择）
POST /api/v1/query/search
{
    "query": "销售技巧",
    "kb_ids": ["kb_001", "kb_003", "kb_005"]  // 用户指定3个
}

# 方式3: 超过限制（返回错误）
POST /api/v1/query/search
{
    "query": "销售技巧",
    "kb_ids": ["kb_001", "kb_002", "kb_003", "kb_004", "kb_005"]  // 5个
}
Response: 400 Bad Request
{ "error": "最多只能同时查询4个知识库", "limit": 4 }
```

```
用户A（销售部）可访问的知识库:
- 租户级: [公司政策, 员工手册]        ← 2个
- 组织级: [销售资料, 产品知识]        ← 2个
```

## 🔒 安全保障

### RLS策略（三级挂载）

```sql
-- 文档访问策略（支持三级挂载）
CREATE POLICY tenant_document_access ON documents
USING (
    kb_id IN (
        -- 租户级
        SELECT kb_id FROM knowledge_base_mounts
        WHERE mount_type = 'tenant'
        AND tenant_id = current_setting('app.current_tenant')::text

        UNION

        -- 组织级
        SELECT kb_id FROM knowledge_base_mounts
        WHERE mount_type = 'organization'
        AND organization_id = current_setting('app.current_organization')::text

        UNION

        -- 用户级
        SELECT kb_id FROM knowledge_base_mounts
        WHERE mount_type = 'user'
        AND user_id = current_setting('app.current_user')::text
    )
);
```

## 💡 关键决策

| 决策点 | 选择 | 理由 |
|-------|-----|------|
| 挂载层级 | 三级（租户/组织/用户） | 满足不同粒度需求 |
| 权限模型 | 累加（Union） | 用户体验最佳 |
| 查询限制 | 4个知识库 | 性能与功能平衡 |
| 组织数据 | 来自子项目0 | 杜绝重复造轮子 |
