# 挂载管理接口使用指南

## 📖 概述

挂载管理接口用于管理知识库的访问权限，支持租户、组织、用户三级权限管理。

---

## 🔐 认证

所有接口都需要 JWT Token 认证：

```bash
Authorization: Bearer <JWT_TOKEN>
```

---

## 🚀 快速开始

### 1. 查看我的所有挂载

获取当前用户可以访问的所有知识库挂载：

```bash
curl -H "Authorization: Bearer ${TOKEN}" \
  http://localhost:8080/api/v1/user/mounts
```

**响应示例：**
```json
{
  "success": true,
  "data": {
    "mounts": [
      {
        "id": 1,
        "kb_id": "kb_123",
        "mount_type": "tenant",
        "tenant_id": "tenant_001",
        "permissions": {
          "can_read": true,
          "can_write": true
        },
        "is_active": true,
        "mounted_at": "2025-11-18T10:00:00Z"
      }
    ],
    "total": 15,
    "breakdown": {
      "tenant_mounts": 5,
      "organization_mounts": 7,
      "user_mounts": 3
    }
  }
}
```

查看谁有权访问某个知识库：

```bash

  http://localhost:8080/api/v1/mounts/1
```

### 4. 更新挂载权限

```bash
curl -X PUT \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "permissions": {
      "can_read": true,
      "can_write": false,
      "can_delete": false,
      "can_share": false

```

**响应示例：**
```json
{
  "success": true,
  "data": {
    "message": "Permissions updated successfully"
  }
}
```

## 📋 接口列表

### 1. 获取知识库的挂载列表

**端点：** `GET /api/v1/knowledge-bases/:id/mounts`

**用途：** 查看谁有权访问某个知识库

**示例：**
```bash
GET /api/v1/knowledge-bases/kb_123/mounts
```

---

### 2. 获取挂载列表（支持过滤）

**端点：** `GET /api/v1/mounts`

**查询参数：**
- `mount_type` (可选) - 挂载类型：tenant/organization/user
- `tenant_id` (可选) - 按租户ID过滤
- `organization_id` (可选) - 按组织ID过滤
- `user_id` (可选) - 按用户ID过滤

**示例：**
```bash
# 获取所有租户级挂载
GET /api/v1/mounts?mount_type=tenant

# 获取特定租户的挂载
GET /api/v1/mounts?tenant_id=tenant_001

# 获取特定组织的挂载
GET /api/v1/mounts?mount_type=organization&organization_id=org_001

# 获取特定用户的挂载
GET /api/v1/mounts?mount_type=user&user_id=user_456
```

---

### 3. 获取单个挂载详情

**端点：** `GET /api/v1/mounts/:id`

**示例：**
```bash
GET /api/v1/mounts/1
```

---

### 4. 更新挂载权限

**端点：** `PUT /api/v1/mounts/:id/permissions`

**请求体：**
```json
{
  "permissions": {
    "can_read": true,
    "can_write": false,
    "can_delete": false,
    "can_share": false
  }
}
```

**示例：**
```bash
PUT /api/v1/mounts/1/permissions
Content-Type: application/json

{
  "permissions": {
    "can_read": true,
    "can_write": false,
    "can_delete": false,
    "can_share": false
  }
}
```

---

### 5. 获取当前用户的所有挂载

**端点：** `GET /api/v1/user/mounts`

**用途：** 获取当前用户通过租户、组织和个人级别可以访问的所有知识库

**特点：**
- 自动合并三级挂载
- 去重（同一知识库只显示一次）
- 提供分级统计

**示例：**
```bash
GET /api/v1/user/mounts
```

**响应：**
```json
{
  "success": true,
  "data": {
    "mounts": [...],
    "total": 15,
    "breakdown": {
      "tenant_mounts": 5,
      "organization_mounts": 7,
      "user_mounts": 3
    }
  }
}
```

## 🔑 权限说明

### 权限类型

| 权限 | 说明 |
|-----|------|
| `can_read` | 可以查看知识库和搜索文档 |
| `can_write` | 可以上传和编辑文档 |
| `can_delete` | 可以删除文档 |
| `can_share` | 可以分享知识库给其他用户 |

### 三级挂载

1. **租户级挂载 (Tenant)** - 租户内所有用户都可访问
2. **组织级挂载 (Organization)** - 组织内所有用户都可访问
3. **用户级挂载 (User)** - 仅特定用户可访问

**权限继承规则：**
- 用户可以访问租户级、组织级、用户级的所有挂载
- 更高级别的权限会被更低级别覆盖（用户 > 组织 > 租户）

## 📊 使用场景

### 场景 1：权限管理页面

在管理后台显示知识库的访问权限：

```javascript
// 获取知识库挂载列表
const response = await fetch(`/api/v1/knowledge-bases/${kbId}/mounts`, {
  headers: { 'Authorization': `Bearer ${token}` }
});
const { mounts } = await response.json();

// 显示权限列表
mounts.forEach(mount => {
  console.log(`${mount.mount_type}: ${mount.tenant_id || mount.organization_id || mount.user_id}`);
  console.log(`Permissions:`, mount.permissions);
});
```

### 场景 2：用户权限审计

查看用户有权访问哪些知识库：

```javascript
// 获取用户的所有挂载
const response = await fetch('/api/v1/user/mounts', {
  headers: { 'Authorization': `Bearer ${token}` }
});
const { mounts, breakdown } = await response.json();

console.log(`总共可访问 ${mounts.length} 个知识库`);
console.log(`租户级: ${breakdown.tenant_mounts}`);
console.log(`组织级: ${breakdown.organization_mounts}`);
console.log(`个人级: ${breakdown.user_mounts}`);
```

### 场景 3：权限修改

更新用户对知识库的权限：

```javascript
// 更新权限为只读
await fetch(`/api/v1/mounts/${mountId}/permissions`, {
  method: 'PUT',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    permissions: {
      can_read: true,
      can_write: false,
      can_delete: false,
      can_share: false
    }
  })
});
```

### 场景 4：组织管理

查看组织内的所有知识库访问权限：

```javascript
// 获取组织的挂载列表
const response = await fetch('/api/v1/mounts?mount_type=organization', {
  headers: { 'Authorization': `Bearer ${token}` }
});
const { mounts } = await response.json();

// 显示组织内的知识库访问情况
mounts.forEach(mount => {
  console.log(`KB: ${mount.kb_id}, Org: ${mount.organization_id}`);
});
```

## 🛠️ 错误处理

### 常见错误码

| 状态码 | 说明 | 原因 |
|-------|------|------|
| 400 | Bad Request | 请求参数错误或缺失 |
| 401 | Unauthorized | Token 无效或过期 |
| 404 | Not Found | 挂载或知识库不存在 |
| 500 | Internal Server Error | 服务器内部错误 |

### 错误响应示例

```json
{
  "success": false,
  "error": {
    "message": "Mount not found",
    "code": "MOUNT_NOT_FOUND"
  }
}
```

## 💡 最佳实践

1. **权限最小化原则** - 只授予必要的权限
2. **定期审计** - 定期检查用户的访问权限
3. **使用组织级挂载** - 对于团队共享的知识库，优先使用组织级挂载
4. **及时撤销** - 当用户离职或角色变更时，及时撤销挂载
5. **日志记录** - 记录所有权限变更操作，便于审计
